# Flutter Mastery Path

Flutter builds apps for Android, iOS, the web, Windows, macOS and Linux from one Dart codebase,
and it does so differently from most UI toolkits: instead of wrapping each platform's native
buttons and lists, it draws every pixel itself, from a tree of small immutable widgets rebuilt
whenever something changes. That design is why Flutter apps look identical everywhere and
animate smoothly — and it's also why Flutter's problems are recognisable: an overflow stripe
because a child ignored its constraints, a text field that empties itself when it's wrapped in a
`Padding`, a list whose ticks stay put when the rows move, a spinner that freezes while JSON is
parsed, a screen that rebuilds sixty times a second for no reason. This course teaches you to
build Flutter apps and to understand the framework well enough to avoid all of those.

**Level 1** starts from the engine and the widget tree: setup, composition, the constraints
model, stateful widgets and their lifecycle, forms, lists and keys, Material 3 theming and
assets — ending with a tip splitter covered by widget tests. **Level 2** builds real apps:
navigation and `go_router`, `InheritedWidget`, Provider and Riverpod with measured rebuilds,
async UI, a typed HTTP client, local persistence, and unit, widget and golden tests — ending with
a reading-list app. **Level 3** goes underneath and outward: elements and keys, implicit and
explicit animations, `CustomPainter`, responsive layouts, platform channels, isolates, Bloc,
accessibility and localization, integration tests — ending with an offline-first habit tracker
with a persisted sync queue. **Level 4** is production: the rendering pipeline and a custom
`RenderObject`, performance, architecture and dependency injection, configuration and flavors, CI,
store publishing, the web and desktop, plugins and `dart:ffi`, upgrades — and a production-ready
expense tracker capstone.

Every lesson has a **How It Actually Works** section — how `setState` turns into a rebuild of
exactly the dirty elements, why a key moves state with a row, how a `FadeTransition` animates
without rebuilding anything, what bytes a platform channel really sends, how a router derives a
whole page stack from one URL.

!!! note "Run, not imagined"
    Code, commands, test output and error messages in this course come from real runs on
    **Flutter 3.44.8 (stable)** with **Dart 3.12.2**, using **go_router 18.0.2**,
    **flutter_riverpod 3.4.3**, **provider 6.1.5+1**, **flutter_bloc 9.1.1**, **http 1.6.0**,
    **shared_preferences 2.5.6** and **intl 0.20.2**. Most examples are verified as widget tests,
    which render real widgets headlessly. Several lessons show first attempts that failed — a
    `setState` that returned a `Future`, a semantics label without a text direction, a format
    check that failed 57 files — because you'll meet those too. The machine used could build for
    the web but not for Android (SDK licenses not accepted), iOS or macOS (no Xcode), and had no
    device attached; lessons that involve devices, native code or store accounts say exactly what
    was and wasn't run. Timings and sizes are one machine's results, not benchmarks.

## How to use this site

- **Know your Dart first.** Flutter code is Dart: classes, null safety, `async`/`await`,
  `Future`s and `Stream`s, records and pattern matching. If those are unfamiliar, start with
  [Dart Mastery Path](https://learnmasterypath.com/dart-mastery-path/).
- **Run the tests, not just the app.** Almost every lesson's code comes with a widget test that
  prints what happened. You can run them with only the Flutter SDK — no phone, emulator or
  simulator — and compare your output with the lesson's.
- **Count rebuilds when something is slow or strange.** Several lessons add a build counter to
  show exactly which widgets rebuilt; it's the quickest way to understand Flutter's behaviour.
- **Related courses.** For the native side of platform channels, see
  [Kotlin Mastery Path](https://learnmasterypath.com/kotlin-mastery-path/) and
  [Swift Mastery Path](https://learnmasterypath.com/swift-mastery-path/); for the APIs your app
  calls, [REST API Mastery Path](https://learnmasterypath.com/rest-api-mastery-path/); for CI,
  [GitHub & Git Mastery Path](https://learnmasterypath.com/github-mastery-path/); for a
  web-first alternative, [React Mastery Path](https://learnmasterypath.com/react-mastery-path/).
- Do the **Exercise** at the end of each lesson; the module-10 projects build on them.
